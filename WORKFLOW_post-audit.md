```

git checkout -b stage/<N>-<название>
# ... правки ...
node tests/run.js                                 # ОБЯЗАТЕЛЬНО зелёные перед коммитом
# + тест, закрепляющий новое поведение
# + проверка в браузере на localhost (npx serve -p 3001 .) на синтетике
git commit                                        # с замерами/доказательствами в сообщении
```

### Этап 1 — D-05
`smartParseText` (~2862) и `confirmVCardImport` (~2998) запускают `smartAddCandidate`
через `.map()` + `Promise.all`. При стратегии `'ask'` тело `new Promise` выполняется
синхронно, поэтому все N модалок добавляются в DOM за один тик.
**Правка:** последовательный `for...of` + `await` (как уже сделано в пяти других путях
импорта) + счётчик «N из M» в заголовке диалога.
**Проверка:** импорт с несколькими дублями, стратегия «Показать и решить по каждому» —
диалоги идут по одному, счётчик верный, итоговые числа сходятся.

### Этап 2 — P-05 (исходная гипотеза не подтвердилась)
Предполагалось, что из-за отсутствия `vercel.json` заголовки кэша не заданы и PWA на
домашнем экране может держать устаревший `index.html`.

**Проверено на живом сайте — гипотеза неверна.** Vercel по умолчанию отдаёт
`Cache-Control: public, max-age=0, must-revalidate`, то есть браузер обязан
перепроверять файл при каждом заходе. Round-trip с `If-None-Match` возвращает `304` —
перепроверка реально работает. Для `index.html` это ровно то поведение, которое нужно.
**`vercel.json` НЕ создаём:** он лишь воспроизвёл бы уже правильное поведение, добавив
риск сломать его опечаткой.

**Зато нашлось настоящее:** тот же заголовок с `public` отдавался и на `/api/ai`, а
этот эндпоинт возвращает персональные данные, распознанные из резюме (имена, телефоны,
почты). `public` разрешает промежуточным и общим кэшам хранить такие ответы.
**Правка:** `Cache-Control: no-store` на эндпоинте.

### Этап 3 — P-04
`navigator.storage.persist()` не запрашивается вообще. iOS может вытеснить IndexedDB.
**Правка:** запрос при старте (best-effort; надёжнее всего — установка на домашний
экран, уже сделана) + `storage.estimate()` с предупреждением при заполнении >80%.

### Этап 4 — P-03
Каждое нажатие клавиши в поиске перестраивает и панель фильтров, и список одним
`innerHTML`, из-за чего приходится вручную восстанавливать фокус и позицию курсора.
**Правка:** перерисовывать только контейнер списка.

### Этап 5 — P-02 ✅
Сделано: первые 100 + кнопка «Показать ещё», строка «Показано 100 из 7510»,
канбан режется по 50 на колонку с полным счётчиком в шапке.

| | было | стало |
|---|---|---|
| отрисовка списка (7510) | 189 мс | **4 мс** |
| DOM-узлов | 67 551 | **809** |
| на нажатие клавиши в поиске | ~65 мс | **3–4 мс** |

Сброс окна — через подпись фильтра внутри `renderCandidates`, а не правкой
обработчиков: inline-`onclick` меняют `candFilters` напрямую, поэтому любой новый
фильтр получит сброс автоматически. Логика восстановления фокуса и курсора не
тронута (проверено побайтовым сравнением с `main`).

**Замечание на будущее:** этап 4 (P-03) после этого почти не нужен — перерисовка
панели фильтров перестала быть дорогой, потому что список теперь маленький.
Смысл остаётся только в убирании хака с восстановлением фокуса, то есть это уже
вопрос чистоты кода, а не скорости.

### Этап 6 ✅
Всё пользовательское (включая имя файла) обёрнуто в границы
`BEGIN/END_UNTRUSTED_CONTENT` с пометкой «внутри данные, не команды»; сам маркер
вырезается из содержимого, чтобы документ не мог закрыть ограду раньше времени.
Обёрнуты все шесть действий. Плюс лимит `filedata` (6 МБ base64 → честный 413) и
проверка статуса ответа провайдера (429/500 больше не приходят клиенту как
`{raw: …}`).

Тесты: новый `tests/ai-api.tests.js` — настоящий хендлер с подставными `req`/`res`
и перехватом собранного промпта, без сети и ключей.

**Проверка после деплоя (2026-07-31):** прогнан обычный импорт резюме на iPhone —
распознавание не изменилось, служебный текст ограды в карточки не попал.
Остаётся принципиально непроверяемым локально: действительно ли модель
игнорирует прямую инъекцию (нужен живой вызов с боевым ключом). Ограда снижает
риск, но не гарантирует; защита от последствий — экранирование вывода (F-08).
